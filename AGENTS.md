# Working conventions for this repo

- **Minimize dialogue.** Keep responses terse — critical messages and summaries only, no play-by-play narration.
- **Worker deployment:** do not use Wrangler (Windows ARM64 has no `workerd` build). Prefer the repository REST uploader because Cloudflare Quick Edit can open the generated ~575 KB bundle read-only: run `npm run bundle-worker`, `npm run validate-worker`, and `npm test`, then set `CF_D1_DATABASE_ID=a9c154d5-ffcd-472d-ae78-aab806420746` and run `node scripts/deploy-worker.cjs`. The configured `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` are used automatically; the script strictly inherits `APP_KEY`/`ALLOWED_ORIGIN` and preserves the `DB`/`PUZZLE_ROOM` bindings.
- Never set `CF_APPLY_MIGRATION=1` for a normal deployment. Use it only for the first deployment of a genuinely new Durable Object class. If the class name changes, recreate/migrate its binding deliberately rather than relying on Quick Edit.
- Verify every Worker release in Cloudflare's version list, then smoke-test `GET /data`. Verify the frontend with a cache-busted GitHub Pages load and check the browser console for errors.
- Before any preview check: unregister service workers + clear caches, then reload. The production Worker rejects localhost by origin; for local UI testing, temporarily use the local-backend placeholder in `config.js`, restore the production URL before committing, and prefer a clean browser origin/context so a cached `config.js` cannot mask the change.
- Before `git push`: `git fetch` + check `origin/main` for new commits — merge if needed. Live gameplay data is stored in D1 and no longer changes this working tree.
- Bump `sw.js`'s `CACHE_NAME` on every shipped change.
- Root scripts are ESM (`package.json` has `"type": "module"`); the older CommonJS scripts are `.cjs`.
- **Design-implementation tasks aren't done until verified against the reference, element by element.** Rendering without errors is not the same as matching the design. Before marking any visual/redesign task complete: reload the actual live/preview page (cache-busted), and check every distinct element named in `design_handoff_across_mobile/Look and Feel Options.dc.html` — colors, spacing, order, badges, icons, copy — against that reference directly, not from memory of having "already built that." Do this per screen as each is finished, not as one pass at the very end.
- **For major/new-feature work, ask clarifying questions one-by-one before planning.** Don't guess at ambiguous requirements or batch every open question into one message — surface them one at a time, let the answer inform the next question, then present a plan for confirmation before handing off to an executing agent.
- Revealed cells (Assist menu) are attributed to no player and excluded from all stats. Auto Check is a binary per-puzzle-session flag on a player — if it was ever on during that puzzle, that whole puzzle's contribution counts at half weight for that player.
- Player color (OKLCH hue) is assigned once per account, globally, at first-ever use — never reassigned, never per-puzzle.
- Test every supported puzzle size for exact output dimensions. Dense-template failures fall back to the legacy generator, which must preserve the selected grid dimensions and must not crop the result.
- Difficulty is clue-corpus filtering and prioritization, not grid density. The corpus now has roughly 9,100 unique usable 3–15-letter answers, three native clue tiers feeding five player-facing profiles, and coverage for all 24 categories. Keep density work separate and preserve the current light block-cell design language unless the user explicitly revisits it.
